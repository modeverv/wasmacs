01

まず、こんなふうに話したい。

約 1 分の導入。エディタの好みを越えて共有できる話から。

Emacs 好きが「Emacs は環境なんだ」と言うと、だいたい話が長くなるんですが、今日はボタンひとつで説明できます。

このボタンを押すと、ブラウザの中にいる本物の Emacs が Lisp を実行するんです。Lisp が状態を更新して、次の画面を組み立てて、前の画面との差分を計算する。JavaScript がそれを DOM に反映します。

React でおなじみの「状態から UI を作る」を、Emacs Lisp で作ってみた。それを動かしているのが、Emacs 本体を WebAssembly に載せた wasmacs です。

面白いのはここで、Emacs をブラウザで使えるようにしたら、今度は Emacs を使ってブラウザのアプリを作れるようになった。

VS Code でコードを書いていても、この面白さは共有できると思うんです。エディタとして知っていたものが、Web アプリの実行エンジンとして働いているんですよ。

説明用に作成した語り口の案です。実在の人物の発言や、作者の逐語引用ではありません。

04

括弧の中にも、見慣れた UI がある。

elisp-react の既存 API を使ったカウンター。コンポーネントを宣言し、状態から表示を返す。

counter.el / Emacs Lisp
;;; -*- lexical-binding: t; -*-
(react-define-component 'counter
  :initial-state
  (lambda (props)
    (list :count (or (plist-get props :start) 0)))
  :render
  (lambda (self)
    `(div (:class "counter")
       (p () ,(format "Count: %d"
                      (react-state self :count)))
       (button
        (:on-click
         ,(lambda (_event)
            (react-set-state self :count
              (1+ (react-state self :count)))))
        "+1"))))

(react-mount '(counter (:start 3)) "#app")
STATE → VIEW

数字から、UI の木を返す。

react-state で状態を読み、render が要素の木を返します。div や button は Lisp のリストです。

EVENT → STATE

イベントに、関数を渡す。

lambda は無名関数。self を捕まえたクロージャが、そのカウンターの状態を更新します。JS 側に増分のロジックを書く必要はありません。

CODE AS DATA

UI も、Lisp が扱えるデータ。

バッククォートはリストのひな型、カンマは式の結果を埋める位置。JSX に慣れた人向けには、同じリストを作る jsx マクロもあります。

動く仕組みが、すでにある。

EXPERIMENTAL

フレームワークとしては発展途上。

  • 初回は Emacs 一式で約150 MB。後続起動向けのキャッシュあり。
  • 非同期 API はコールバック式。返らない Lisp 処理を止めるには Worker の終了・再起動が必要。
  • SVG・context・再描画の細かな最適化などに未対応の領域。
  • Worker の状態は再読み込みで失われる。保存したいアプリデータは別に扱う。

この資料を作る際の確認：公開カウンターで Apples 3 → 4 → reset 0、Oranges 0 → 1 の表示変化をブラウザで確認。ネイティブ Emacs の Lisp テストは 25 / 25 成功。

他の公開例のブラウザ動作を網羅的に再試験したわけではありません。速度比較も実施していません。実装内容はソース確認、UI の実測は上記カウンターの範囲です。

wasmacs のエディタ本体と eval service は用途が異なります。エディタ側のファイル永続化やサブプロセス機能が、そのままこのサービスに備わるわけではありません。

07

たぶん、こう聞かれる。

「React でよくない？」

アプリを作る選択肢として React は自然です。この実験では、UI の状態管理と差分計算を別の言語・実行環境で組み立てることで、フレームワークの仕組みと Emacs の使い道を探れます。その過程そのものが楽しいんです。

「Emacs を覚えないと楽しめない？」

入口は、状態・関数・イベント・DOM です。普段のエディタで .el を書いても構いません。Web 開発の知識を使って、クリックから描画までを読めます。

「それ、Lisp を JavaScript に変換しているの？」

Elisp は WebAssembly 化された GNU Emacs で評価します。ブラウザとの接点に JavaScript は使いますが、コンポーネントのロジックや差分計算を実行するのは Emacs です。

「Emacs の資産が、そのまま全部 Web で使える？」

使える範囲は各パッケージが要求する機能次第です。eval service はリクエストを順番に評価するエンジンで、通常の対話 Emacs と同じ常駐イベントループや OS 機能を備えてはいません。elisp-react は必要なブラウザ機能を、明示的なホスト連携で足しています。

「Emacs は環境なんだ」が、
ブラウザのボタンひとつで伝わる。

Emacs Church 的な愛着を、状態・関数・プロトコルという共通言語にすると、この実験の面白さが届きます。
